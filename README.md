В этом проекте мы потренируемся в mutation testing, создавая unit-тесты для модуля расчёта платежей.

Ниже необходимо описать какие действия или стратегия доработок были выбраны во время выполнения задания

# Стратегии доработок тестов

Соответственно для проверки на мутации я проверяла сценарии с различными входными данными, включая граничные значения, 
типовые бизнес-кейсы и крайние случаи (edge cases). Также я включила в тестирование условия, арифметические операцие и округления,
так как именно в этих местах чаще всего возникают логические ошибки, которые могут не выявляться при стандартном покрытии тестами.

Таким образом был разработан набор тестов, который не только покрывает код по строкам, 
но и проверяет корректность поведения функций при изменении ключевых показателей и элементов логики.

Ниже представлены основные факторы, которыми я руководствовалась при разработке тестов.

## Для обеспечения coverage

* Проверяла, что каждая функция покрыта тестами
* Проверяла кажду ветку функции
* Проверяла отдельные условия

## Для проверки логики 

* Проверяла базовый сценарий
* Проверяла позитивные и негативные сценарии
* Проверяла граничные случаи
* Проверяла переходы между различными состояниями

## Для проверки мутаций

* Проверяла арифметические мутации (корректность математической логики)
* Проверяла логические мутации (различные комбинации условий)
* Проверяла константы
* Проверяла округления
